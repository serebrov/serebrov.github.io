#+TITLE: Blog

The org-mode content for https://serebrov.github.io.

The live site is updated by the [[.github/workflows/orgmode.yaml][GitHub action]] that rebuilds live pages:
 * Checks out the `public-pages` branch (this is used as a source for public pages)
 * Runs =make build= to build static content.
 * Deploys "public" folder.

* Static Files Build Process

A static blog made from org files with the Emacs HTML exporter (=ox-html=).

The HTML is built with file:publish.el.
Common layout is defined in file:layout/header.html and file:layout/footer.html.
Some extra features are added with custom javascript (file:static/blog.js, file:static/config-preview.js).

The main content is in file:posts/.

URL are mapped into the =html/= path because this is how it worked in the old setup (this way we don't break indexed pages).

* Requirements
- Emacs with Org 9.8 or later.
- The =htmlize= package.

* Commands
| Command        | Result                                           |
|----------------+--------------------------------------------------|
| =make build=   | Export the posts that changed to =public/=.      |
| =make rebuild= | Export all posts again.                          |
| =make serve=   | Build and serve =public/= on http://localhost:8000. |
| =make clean=   | Remove =public/= and the export cache.           |

In Emacs:
- load =publish.el= and run =M-x blog-publish=
- =C-u M-x blog-publish= to export all posts

=make build= exports only updated org files.

When a file in =layout/=, =publish.el=, or =blog-tags.el= is newer than the last build, =make build= exports all pages again.
The build keeps the time of the last build in =.cache/build-stamp=.

To convert multiple files from markdown to org:

#+begin_src shell
for mdf in $(ls *.md); do pandoc -f markdown -t org -o ${mdf%.*}.org $mdf; done;
#+end_src

* Page features
- Folding :: Page sections are foldable (click a heading). The =:folded:= tag makes the section folded intially on page load.
- Section links :: Each heading has an id based on its title, for example =#code-blocks=. Different ID can be set with =CUSTOM_ID= propperty.
- Code :: htmlize colorizes the code at build time. The colors are defined in file:static/blog.css. Block with code have a "Copy" button.
- Code results :: The code is not executed during build. If necessary, execute the code in Emacs (before publishing). Code blocks that are marked with =:exports both= and have the =#+RESULTS:=  block will be exported to HTML. See the file:posts/2026-09-25-org-demo.org for examples.
- Images :: Image links like =[[file:images/diagram.svg]]= will display the image on the page. Add =#+CAPTION:= to have a caption. Use =M-x yank-media= to paste an image from the clipboard to =posts/images/= and insert the link (see file:posts/.dir-locals.el for related configuration).
- Video :: Added as =[[video:images/clip.mp4]]= or =[[video:https://example.com/clip.mp4]]=. Videos are displayed in the video player.
- Config preview :: The file:static/config-preview.js has custom javascript that displayes links to =.config= files in a popup (and can be easily extended to display other file types too). To use this feature, add =#+HTML_HEAD_EXTRA: <script defer src="/static/config-preview.js"></script>= to the post. See also the [[file:posts/2026-09-25-org-demo.org::*HTML Export][HTML Export]] for the example of custom js/css code in the post body.
- Tags :: Tags are added in the =#+FILETAGS: :git:aws:= format. The =/tags/= page shows all tags and we have a tag cloud on each page.
- Sidebar :: On wide screens, the left column shows the table of contents of the page, the links to the post lists (Posts, Archive), and the tag cloud, with lines between them. The column stays on the screen and scrolls independently of the page. On narrow screens, the table of contents is at the top of the page and the tag cloud is at the bottom.
